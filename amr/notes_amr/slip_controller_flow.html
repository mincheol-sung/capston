0. 채팅 내용 중 바로잡을 것

① "map→base_footprint 포즈 미분은 휠과 무관" 틀림

T_map_base = T_map_odom (ekf_carto ← cartographer) · T_odom_base (ekf_filter_node ← /odom 휠)

뒤쪽 T_odom_base가 휠 오도메트리로 만들어지므로 이 TF를 미분하면 휠 속도가 그대로 섞입니다. /tracked_pose를 직접 써도 현재 설정에서는 섞입니다.

mapping_2d.lua
  use_odometry = true             (75행)  ← 휠 /odom 을 pose extrapolator 에 씀
  use_imu_data = true             (102행)
  use_pose_extrapolator = true    (69행)
localization_2d.lua
  pose_publish_period_sec = 1e-2  (30행)
토픽 (bag 실측)주기
/scan_front10.0 Hz
/scan_rear9.99 Hz
/tracked_pose98.22 Hz ← scan보다 10배
/tracked_pose 10개 중 9개는 scan matching이 아니라 extrapolator가 휠·IMU로 외삽한 값입니다. 채팅의 "cartographer 포즈 약 10 Hz"는 이 스택에 맞지 않습니다. 순수 LiDAR 속도가 필요하면 cartographer를 use_odometry = false로 바꾸거나, rf2o 같은 독립 LiDAR odometry를 두어야 합니다.

② "자기 자신과 비교하면 슬립이 과소추정" 방향은 맞음 실제로는 더 나쁨

휠에서 구한 v = T_FWD·ω_meas를 기준으로 쓰면:

s = ω_meas − T⁻¹·T_FWD·ω_meas = (I − T⁻¹T_FWD)·ω_meas = n nᵀ·s_true,   n = [-1,-1,1,1]/2
수치 확인: ‖(I − T⁻¹T_FWD) − n nᵀ‖ = 2.8e-16

슬립 4성분 중 null 방향 1개만 남습니다. FL만 30% 헛돌게 한 예:

진짜 s      [3.75, 0, 0, 0]
자기비교 s  [0.94, 0.94, -0.94, -0.94]   ← 크기 1/4, 어느 바퀴인지 구분 불가

③ "M·v̇ = (1/r)·Bᵀ·τ" v가 body frame이면 틀림

회전 좌표계에서는 ω × v 항이 필요합니다.

m (v̇x − ωz·vy) = Fx
m (v̇y + ωz·vx) = Fy
I_z ω̇z         = Mz           [Fx, Fy, Mz]ᵀ = (1/r)·Bᵀ·τ

검산 (m = 10 kg은 예시값): vx = 0.5 m/s, ωz = 1 rad/s로 body 속도를 일정하게 유지하려면 Fy = 5 N이 필요합니다. 채팅 식으로는 F = 0 → v̇ = 0이라 이 5 N을 설명하지 못합니다.

F = Bᵀτ/r (일률 보존 τᵀω = Fᵀv) 자체는 맞습니다. 검산 오차 0.0.

④ 추가: 토크 모드의 "0 명령"은 정지가 아님

속도 모드의 [0,0,0,0]은 "바퀴를 멈춰라", 토크 모드의 τ = 0은 "힘을 빼라"입니다. 굴러가던 로봇은 마찰로 감속할 때까지 계속 굴러갑니다. 게이트 timeout·disarm 동작(감속 토크 / damping 모드 / 속도 0 명령 전환)을 새로 정해야 합니다.

#항목내용
①토픽 이름/wheel_cmd를 토크용으로 재사용 금지. 단위가 rad/s → N·m로 바뀌는데, 옛 드라이버가 떠 있으면 토크를 속도로 해석함
②변수명 충돌증강 MPC 입력 Δτ_MPC(스텝 변화량) ≠ 보상기 출력 Δτ_slip(보정량)
③제약 여유MPC 제약 |τ_i| ≤ τ_limit − Δτ_slip,max
④MPC 속도 상태 출처채팅에서 빠진 부분. 보상기는 10 Hz여도 되지만 MPC는 10 ms마다 v가 필요함 (아래 표)
④ 선택지휠 정보 섞임비고
(a) LiDAR 10 Hz 포즈 + 토크 입력 모델 Kalman 예측없음모델이 틀리면(슬립 d) v도 틀림
(b) (a) + IMU(ωz, 가속도) 융합없음IMU 사용은 허용 상태
(c) LiDAR v를 다음 갱신까지 유지 (ZOH)없음최대 100 ms 늦은 상태로 제어
(a)/(b)를 쓸 때는 슬립용 v와 MPC용 v를 같은 추정기에서 받을지 분리할지도 정해야 합니다. 추정기 예측에 d = 0 가정이 들어가기 때문입니다.

# 노면별 마찰계수 μ̂ 측정 절차 (2026-11-17, 전준민)

비교군 C 의 토크 상한 τ_μ = (r/√2)·μ̂·(m g/4)·c_s 는 **노면마다 잰 μ̂ 를 상수로** 쓴다.
C 의 MPC 는 "슬립 없음" 모델이고, 이 상한으로 그 가정을 지킨다 — μ̂ 가 크면 미끄러지고(B 처럼), 작으면 쓸데없이 느리다.
μ̂ 를 바꿔 가며 돌리는 것은 민감도 분석이고, **A·B·C 본 비교에는 그 노면에서 잰 μ̂** 를 쓴다.

| 무엇 | 어디 |
|---|---|
| 한 판 측정 (토크 램프 → 슬립 판정 → 미끄러지는 동안 몸체 가속으로 μ̂) | `tools/mu_ramp_test.py` (`amrmu`, 성민철 2026-11-16, 시뮬 검증) |
| 여러 판·여러 날을 모아 노면 대표값 → 표에 저장 | `tools/mu_surface.py` |
| 노면 표 | `config/surfaces.yaml` |
| 실행 때 노면 이름으로 μ̂ | launch `surface:=<이름>` (`amrall`·`torque_experiment`). `mu_hat:=값` 을 주면 그쪽이 이긴다 |
| 계산·판정 규칙 (ROS 없음) | `amr_mpc/core/surfaces.py`, 시험 `test/test_mu_surface.py` |

## 0. 준비
- 노면 이름을 정한다: 영문·숫자·`_` (예: `lab_floor`, `lab_carpet`, `corridor_tile`). 같은 바닥이라도 청소·코팅이 다르면 다른 이름
- 체크리스트 5-0 (수동 정지 두 명, 배터리 셀 전압 ≥ 3.5 V/셀, 측위 확인). 바퀴 청소 (먼지가 μ 를 바꾼다)
- 질량 확인: `torque_plant.yaml` `body.mass_kg` (+ `payload_kg`). μ̂ 는 질량과 독립이지만 계산에 m 이 들어가므로 실제 질량과 같아야 한다
- 공간: 시험 방향으로 **1.5 m 이상**, 옆으로 0.5 m 이상 비우기. 바닥에 출발 표시
- 토크 램프가 바퀴를 헛돌린다 — 같은 자리에서 반복하면 바닥 자국·바퀴 마모. 조금씩 옮겨서

## 1. 측정 — `mu_ramp_test.py` (주 방법)
```
amrall                                    # 터미널 1: MPC 없이 (use_mpc 기본 false). CAN·추정기·IMU
cd ~/capston/capston/src/amr_basic_stack/controller/mpc
/usr/bin/python3 tools/mu_ramp_test.py --dirs fwd,back --repeat 5 \
    --csv ~/capston/capston/analysis/torque_mpc_real/<날짜>_mu/<노면>_fb      # 터미널 2
```
- **앞·뒤를 각 5 판 이상** (주 방향). 판마다 Enter, 로봇을 출발 표시로 되돌린다
- 옆도 볼 때: `--dirs left,right --repeat 5 --csv …/<노면>_lr` (참고 방향 — 롤러 손실·IMU 잡음으로 흩어짐이 크다)
- 기본값: 램프 2 N·m/s, 최대 0.35 N·m, 슬립 판정 뒤 0.3 s 유지. 끝까지 안 미끄러지면 "슬립 없음" = μ̂ 하한 → `--max` 를 0.45 까지 올려 다시
- 판마다 화면에 `μ̂ (롤러 모델) = …` / `★ 슬립 확인 안 됨 — 버림` / `μ̂ ≥ … (하한)` 이 나온다. 버림이 절반을 넘으면 바닥·배터리·판정 문턱을 의심
- 다른 날·다른 배터리 상태로 **한 번 더** (하루 5 판 × 2 일 권장). 바닥 상태가 날마다 바뀌는지 본다

`torque_ramp_node` (`amrramp`, YuMin1024 2026-11-17) 기록도 섞어 쓸 수 있다 (아래 `--ramp-node`). 다만 이 노드는 슬립 뒤에도
토크를 계속 올려 유지 구간이 없어서 판정을 기록에 다시 적용한다 — `mu_ramp_test` 를 주 방법으로.

## 2. 정리 — `mu_surface.py`
```
python3 tools/mu_surface.py summarize --surface <노면> \
    --summary ~/capston/capston/analysis/torque_mpc_real/*_mu/<노면>_*_summary.csv \
    [--ramp-node …/ramp_*.csv] --note "바닥 청소 뒤, 배터리 24.6 V" --write
python3 tools/mu_surface.py list
```
판정 규칙 (`surfaces.summarize`):
- 판 결과: **slip** (μ̂ 확정) / **no_slip** (하한) / **unconfirmed** (버림)
- 방향마다 slip 판의 **중앙값**. 주 방향(기본 앞·뒤)마다 **5 판 이상**이어야 `확정`, 아니면 `부족`
- **추천 μ̂ = 주 방향 중앙값 중 가장 작은 값** (어느 주 방향으로도 상한보다 먼저 미끄러지지 않게)
- 경고: 옆 방향 중앙값이 추천의 85 % 미만 / 슬립 없는 판의 하한이 추천보다 10 % 넘게 큼 / 한 방향 흩어짐 (최대−최소)/중앙 > 40 %
- `--write` 는 리포의 `config/surfaces.yaml` 에 근거(판 수·중앙값·범위·날짜·기록 파일)와 함께 쓴다. **손으로 고치지 않는다**
- 쓴 뒤 다시 빌드(`amrb`)해야 launch 가 읽는다. 커밋할 때 `analysis/…_mu/` 기록도 같이

## 3. 쓰기
```
amrall use_mpc:=true limit_mode:=friction surface:=<노면> …
```
- 로그 첫머리에 `surface:=<노면> → μ̂ …` 가 나온다. 표에 없거나 `mu_hat: null`(미측정) 이면 **실행을 거부**한다 (조용히 0.3 으로 가지 않게)
- 민감도 시험은 지금처럼 `mu_hat:=값` (surface 보다 우선)
- 비교군 B(`motor_only`) 에는 μ̂ 가 쓰이지 않는다 — C 일 때만 효과

## 4. 바퀴별 상한 배율 (차체 값, 2026-11-18)
C 의 상한을 바퀴마다 다르게: τ̄_i = min(모터, τ_μ·s_i), `torque_plant.yaml surface.wheel_limit_scale: [FL, FR, RL, RR]` (기본 1 = 예전과 같음).
μ̂ 는 노면마다, s_i 는 차체마다 한 번 정한다 (배터리 위치·적재를 바꾸면 다시).
- 원리: τ_slip,i = (r/√2)·μ·N_i / g_i — 바퀴에 실린 무게 N_i 가 작거나, 모터가 명령보다 센(g_i > 1) 바퀴가 먼저 미끄러진다.
  s_i = (N_i / N̄) / g_i
- 재는 것: ① 하중 — 저울 1 개면 **두 바퀴씩** (앞 합·왼쪽 합, `--front`·`--left`). 앞뒤·좌우 쏠림은 무게중심이 정해 받침 높이에 둔하다.
  바퀴 하나씩 재는 값(`--loads`)은 받침 높이 1 mm 에 대각 쏠림이 흔들리니 저울 4 개로 동시에 잴 때만 ② 느린 램프 `amrramp dir:=fwd rate:=0.4 tau_max:=0.5 distance:=1.5` 5 판 —
  바퀴 표면 속도가 몸체 운동보다 앞서는 순간을 바퀴마다 잡아 그때 모터 보고 토크를 본다 (검산, 하중이 없으면 이것으로 — 낮추기만)
- 정리: `python3 tools/mu_surface.py wheels --loads 1050,1180,1220,1110 --ramp-node …/ramp_*.csv --mu 0.4`
  → 배율·바퀴별 τ̄ 와 YAML 한 줄. 하중으로 가장 약한 바퀴와 램프에서 가장 자주 미끄러진 바퀴가 다르면 경고
- 실행 한 번만 바꿀 때: `amrall … limit_mode:=friction mu_hat:=0.4 wheel_limit_scale:=0.85,1,1.1,1`. 시작 로그에 `바퀴별 τ̄ [FL FR RL RR]`
- 모터 차이 g_i: 11-17 램프에서 모터 보고 토크/명령 = FL 0.94 · FR 0.94 · RL 0.96 · RR 0.95 (2 % 안). 다만 보고 토크도 공칭 토크 상수로 낸
  값이라 진짜 출력 차이는 못 본다 — 필요하면 바퀴를 고정하고 팔 끝을 저울로 눌러 재는 정지 토크 시험으로 (`--motor-gain`)
- 구동계 마찰 차이(FR 이 0.003~0.005 N·m 더 듦)는 torque_output 이 바퀴별로 이미 보상한다 — 배율에 넣지 않는다

## 5. 해석할 때 주의
- μ̂ 는 **미끄러지는 동안(운동 마찰)** 의 값이라 출발 순간(정지 마찰)보다 작거나 같다 → 상한에는 보수 쪽. `c_s` 0.8 이 남은 여유
- **45° 롤러 모델** 기준이다 (`mu_ramp_test`·시뮬 SlipPlant·C 식이 모두 같은 정의). 앞·옆이면 μ̂ = √2·a/g. "몸체 기준(등방)" 값 |a|/g 와 √2 배 다르니 다른 자료와 비교할 때 기준을 맞춘다 (11-15 5-2 의 0.24 / 0.33 이 이 차이)
- 옆걸음은 미끄러지지 않아도 바퀴가 몸체보다 빨리 돈다(효율 0.5~0.6) → 거짓 슬립 판정이 섞이기 쉽다. 그래서 주 방향은 앞·뒤. 옆이 정말 낮으면 C 상한을 방향별로 나누는 것을 검토 (todo "MPC 바닥 마찰 대응")
- 바닥 μ 는 날마다·자리마다 바뀐다 (먼지, 습도, 바퀴 마모). 흩어짐이 크면 판 수를 늘리고 가장 미끄러운 자리 기준으로

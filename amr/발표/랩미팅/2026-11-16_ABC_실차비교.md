# 실차 A·B·C 비교 — circles8 0.7 m/s, 비교군마다 3 판 (2026-11-16 밤 ~ 11-17 낮)

같은 경로·같은 속도로 비교군 A·B·C 를 3 판씩 돌린 결과다. 수치는 모두 bag 에서 스크립트로 계산했다 (`분석_스크립트/`, 맨 아래 "재현").
결론은 **세 판의 범위가 서로 겹치지 않는 것**만 쓴다.

## 2. 측정 방법

| 지표 | 정의 | 출처 |
|---|---|---|
| 슬립률 λ | λ_i = (ω_i − ω_nom,i)·sgn(ω_nom,i) / max(\|ω_i\|, \|ω_nom,i\|, ω_ε), ω_nom = T⁻¹v̂, ω_ε = 2.5 rad/s. λ > 0 헛돎, λ < 0 끌림 | `/slip_logger/slip` (`nodes/slip_logger.py`). v̂ = `/state_estimator/odom` (SLAM + IMU, 바퀴와 독립) |
| 시간 기준 추종 오차 | 그 시각의 기준점과 추정 상태의 차 [e_x, e_y, e_θ] | `/torque_mpc/status`·`/pure_pursuit/status` 앞 4 열 (`fault_monitor` 가 보는 값) |
| 경로 기준 거리 | 추정 위치에서 `/figure8/path` 까지 최단 거리 (늦게 따라가는 것은 오차로 안 침) | `/state_estimator/odom`, `/figure8/path` |
| 명령 토크 | gate 출력 | `/wheel_torque_cmd` (마찰 보상 포함 → C 최대가 τ̄ 보다 큼) |
| 바퀴 포화 | \|ω\| > 38 rad/s 비율 (무부하 최고 약 41~45 rad/s), \|ω\| > 20 rad/s 구간의 부호 뒤집힘 수 | `/wheel_states` |

- λ 식 검산: `2026-11-16/223122_bag` 에서 슬립 행의 t (= `/wheel_states` header.stamp) 로 같은 메시지의 ω 를 찾아 다시 계산 → 4871 행 차이 최대 0
- 모든 통계는 arm 구간 (추종 오차는 기준열이 있는 동안). λ 는 \|v̂\| 0.6–0.9 m/s 구간 (순항) 의 RMS

## 4. 읽은 것 (3 판 범위가 겹치지 않는 것)

- **B 가 모든 항목에서 가장 나쁘다**: 세 판 모두 바퀴 ω 가 ±42~45 rad/s (전압 한계 근처) 사이를 사각파처럼 뒤집히고 (그림 B 왼쪽 열), ω_nom 은 그렇게 뒤집히지 않는다 → 바퀴가 몸체와 따로 돎 (헛돎).
  명령 토크 95 % 값이 1.25 N·m 로 상한 (1.2 + 마찰 보상) 에 붙어 있다. 위치 오차는 A·C 의 2~3 배, 3 판 중 2 판이 arm 11.8 s 에 `pose_jump` 로 정지.
  B 의 λ 에는 추정기 흔들림 (\|ω_nom\| 최대 53~62 rad/s ≈ 몸체 2.1~2.5 m/s, 비물리적) 이 섞여 있다 → 근거는 λ 보다 **바퀴 ω 자체의 뒤집힘** (바퀴 측정값, 추정기와 무관)
- **C 는 B 의 헛돎을 거의 없앤다**: \|ω\| > 38 rad/s 시간 21.8–39.3 % → 0.1–0.5 %, 뒤집힘 → 0. 위치 오차도 B 의 약 절반 이하
- **헤딩은 C 가 A 의 약 1/3** (RMS 1.1–1.3° vs 3.4–3.9°, 최대 6.3–7.1° vs 13.3–18.9°). MPC 비용의 θ 가중 (W 50) vs PP 의 k_heading 비례항 차이로 추정 (원인 미확인)
- **슬립은 A 가 C 보다 작다** (RMS λ 0.12–0.21 vs 0.25–0.45). A 의 상한은 B 와 같은 1.2 N·m 인데도 토크를 작게 냈다 (95 % 0.11 vs C 0.19 N·m) → 슬립이 작은 것은 상한 때문이 아니라 바퀴 속도 PI (kp 0.03, ki 0.15) 가 토크를 작게 낸 결과로 보인다
- **위치 오차는 A 가 C 보다 약간 작다** (시간 기준 RMS 3.5–4.0 vs 4.4–4.9 cm). 경로 기준 거리는 1.9–2.1 vs 2.0–2.2 cm 로 거의 같다
- `torque_mpc_todo.md` 의 기존 항목 "A 가 시뮬에서 B·C 보다 좋게 나온 것 — 발표 결론(C 가 슬립을 줄인다)과 부딪힌다" 와 같은 방향이다. 실차 3 판씩으로도 같다:
  **"C 가 B 보다 슬립을 줄인다" 는 성립, "C 가 A 보다 슬립이 적다" 는 성립하지 않는다**

## 5. 주의·다음 확인

- 추종 오차는 추정기 (`/state_estimator/odom`) 기준 = 제어기가 본 오차. 추정기 자체 오차는 빠져 있다 → SLAM `/tracked_pose` 로 다시 재면 독립 확인
- **C 의 μ̂ 0.6 이 실제보다 클 수 있다**: 실제 μ 가 0.4 면 마찰 한계 0.253 × 0.4 = 0.101 N·m 인데 C 는 0.152 N·m (약 1.5 배) 까지 허용 → C 의 슬립이 A 보다 큰 원인 후보 (가설).
  바닥 μ̂ 를 재고 그 값으로 C 를 다시 돌린다. 2026-11-17 오전 바닥 토크 램프 시험 결과 (`amrramp`, `analysis/torque_mpc_real/2026-11-17_ramp`) 가 있으나 이 문서에서는 아직 분석하지 않았다
- λ 의 잡음 바닥은 추정 속도 오차로 약 0.1 → \|λ\| > 0.1 비율은 슬립과 잡음이 섞인 수치
- B 의 `pose_jump` 가 헛돎 때문인지 (빠른 회전·진동으로 스캔 매칭이 흔들림) 는 이 데이터로 가르지 못했다

## 6. 재현

NUC 에서 (`source /opt/ros/jazzy/setup.bash && source install/setup.bash` 뒤, 작업공간 루트에서):

```bash
A="bags/2026-11-16/225936 bags/2026-11-17/130656 bags/2026-11-17/130822"
B="bags/2026-11-16/225525 bags/2026-11-17/131217 bags/2026-11-17/131333"

for d in $A $B $C; do /usr/bin/python3 src/amr_basic_stack/controller/mpc/tools/plot_slip.py $d; /usr/bin/python3 $Z/slip_bins.py $d; done   # 그림, 속도 구간별 λ
/usr/bin/python3 $Z/wheel_sat.py $A $B $C        # 바퀴 포화·뒤집힘
/usr/bin/python3 $Z/torque_stats.py $A $B $C     # 명령 토크
/usr/bin/python3 $Z/track_compare.py $A $B $C    # 추종 오차·경로 진행
/usr/bin/python3 $Z/run_events.py bags/2026-11-17/131333                     # arm·fault·경고 시각
/usr/bin/python3 $Z/check_slip_def2.py bags/2026-11-16/223122_bag             # λ 식 검산
```

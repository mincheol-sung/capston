###### **Q.** 고전 제어(PID) 대신 MPC를 쓰는 이유?



###### **A.** (정다솔 교수님):



**<흐름도>**

**mpc 장점 -> 한계점 : 모델 불확실성(하중, 노면 변화 + 이에 따른 휠슬립 변화)에 취약 -> 이를 해결 (우리 과제)**

====================================================================================================

**mpc 장점**

&#x09;1. 원하는 대로 cost 튜닝

&#x09;**2(중요)**. 제약조건 설정 가능

&#x09;	PID제어 - %OS를 알 수 없다.

&#x09;	MPC - 제약조건 설정 가능 - ex. 1 모터의 물리적 한계를 넘어서는 제어 입력을 인가하지 않도록 설정할 수 있다.

&#x09;						   2 경로에서 10cm 이내에서 벗어나지 않게 할 수 있다.

&#x09;3. 모델 기반으로 미래를 예측 할 수 있다. (10스텝 미리 input을 계산하는 것과 연관) <->PID는 사후 피드백

&#x09;

**mpc 한계점(단점)**

&#x09;1. 모델 불확실성 (적재 하중 변화, 노면변화 -> 휠슬립 변화 ; 하중, 노면, 휠슬립 세가지 다 모델임)

&#x09;	: 모델 기반 예측인데, 모델이 불확실(적재하중 변화, 노면 변화 등) 하면 제대로 작동 안함.

&#x09;	**-> 이를 해결하기 위한 것이 우리의 과제**

&#x09;2. 연산속도가 느림.

&#x09;		: 해결 방법 -> **우선 제어주기 (ex. 10ms)가 있음. 이 10ms 마다 제어 입력을 주게 되는데, 이 제어 주기 안에만 연산을 마치면, PID나 MPC나** 

&#x09;			  **연산속도에 의한 차이가 없음.**

&#x09;			-> 이를 어떻게 맞출 건데? : 앞서 mpc는 미래의 값을 예측한다고 했음. 지금 50 step 예측하는 데 12ms 가 걸린다.

&#x09;												그러면 **20step 예측으로 줄여서 연산시간을 10ms 이내로 줄여서 해결 가능.**

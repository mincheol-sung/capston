1. 문제 정의
    - 메카넘 휠에 대해
    - 휠슬립 제어의 필요성
    - 현재 AMR의 상태
    
    - AMR 소개 -> 산업현장에서 쓰이는 AMR -> 메카넘 휠의 필요성 -> 메카넘 휠의 문제점 (odometry X) -> 휠슬립 제어기의 필요성 

2. 제품 정의
    - hardware : 모터 교체
        토크 제어 모터 쓰는 이유 - 슬립 제어 하려면, 마찰력에 따른 토크를 제어해야하기 때문.
        AMR 진행 상황 - 컨트롤러로 구동만 되는 상태. 자동으로 경로를 따라가도록 하는 건 아직 안 되어 있음.
    - software : 휠슬립 알고리즘 개발 

    - AMR 제원 소개 (software + hardware) -> 모터 교체 당위성 설명 -> 휠슬립 알고리즘에 대한 plant 폐루프 구조 + 최적제어

    - 이 주제를 왜 하게 되었는지, 설계 목표, 소프트웨어 하드웨어적인 목표를 수치적으로 정량적으로 뽑는 것이 중요하다

정민이형 말씀

MPC를 쓰는 이유
- 고전 제어 방식(PID) : 오차를 차후에 보상한다.슬립이 발생하고 나서 제어가 개입할 수밖에 없음
MPC 
- 제어 입력의 물리적 한계를 명시적으로 설정해줄 수 있다. (hard constraints) 출력의 제약 걸기 (soft constraints)
- 시스템의 모델에 모델 오차, 슬립과 같은 외란을 반영할 수 있다. 모델 오차나 외란을 모델에 반영 함으로써
    미래의 제어 입력에 대한 시스템의 미래 응답을 현실에 가깝게/정밀하게 예측할 수 있다.
이렇게 예측한 
- 과도 응답이나 정상상태 응답 또는 주파수 영역에서의 제어기 설계와는 달리
 비용함수를 활용해서 성능 지표를 정량적으로 표현하고 가중치를 부여해 여러 성능 지표 사이에서 우선순위를 정하는 등 최적의 제어 입력을 찾는 행위에 사용자의 주관을 반영 가능하다.

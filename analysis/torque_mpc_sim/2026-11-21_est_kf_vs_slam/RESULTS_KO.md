### 속도 출처를 wheels 로 하지 않은 이유

| 자리 | 이번 설정 | wheels 로 하면 | 판단 |
|---|---|---|---|
| MPC 속도 상태 (`velocity_source`) | estimator | `torque_mpc_node.cpp` 가 v_x, v_y 를 바퀴 기구학 값으로 덮어쓴다 (ω_z 만 추정기). 추정기가 MPC 에 주는 것이 포즈뿐이다 | 이번 결과에서 kf 와 slam 이 가장 크게 다른 항목이 속도 오차(4.5 vs 9.3 cm/s)다. wheels 로 바꾸면 그 차이가 제어기에 닿지 않아 추정기 비교가 아니게 된다. 바퀴 값은 슬립(λ)도 그대로 섞인다 |
| A 의 바퀴 PI 되먹임 (`pp_speed_source`) | 이번엔 A 를 돌리지 않음 | 기본값이 wheels (엔코더 ω_i) | 바퀴 PI 는 crossover 19~49 rad/s 로 엔코더용으로 설계된 빠른 루프다. 아래 2.3 의 slam 실효 지연 τ = 89.8 ms 를 넣으면 지연 하나로 잃는 위상이 ω_c·τ = 1.71~4.40 rad (98°~252°)다. 지연만으로 phase margin 45° 를 넘지 않으려면 ω_c < 0.785/0.0898 = 8.7 rad/s 로 다시 튜닝해야 한다. kf 는 시뮬에서 지연이 0 ms (10 ms 해상도)지만 속도 잡음이 4.5 cm/s RMS 다. 실차 A + estimator 되먹임 판(181457, 추정기는 kf)에서 \|ω\| > 38 rad/s 가 24.9 %, \|e\| RMS 35.7 cm 였다. A 로 추정기를 시험하려면 PI 재튜닝이 먼저다. 그게 아니면 내부 루프는 엔코더로 두고, PP 바깥 루프만 추정기 포즈를 쓰는 지금 구성이 맞다 |

### 2.3 slam 속도 오차는 구조에서 나온다

slam 모드 (`estimator.py::_pose_slam`): 포즈가 들어올 때마다 속도를 v_k = v_{k−1} + α·((z_k − z_{k−1})/Δt − v_{k−1}) 로 덮어쓴다.
Δt = 0.1 s, f_c = 2 Hz → α = 1 − exp(−2π·f_c·Δt) = 0.7154, β = 1 − α.

| 항목 | 식 | 값 |
|---|---|---|
| backward difference 의 group delay | Δt/2 (2-tap linear-phase FIR; Oppenheim & Schafer, *Discrete-Time Signal Processing*) | 50.0 ms |
| first-order IIR low-pass 의 DC group delay | β/α 샘플 | 0.398 샘플 = 39.8 ms |
| 실효 지연 τ | 합 | **89.8 ms** |
| 포즈 잡음 몫 (축당) | (σ/Δt)·√(2α²/(1+β)) | 1.79 cm/s → 2D 2.52 cm/s |

참값 궤적을 10 Hz 로 뽑아 같은 차분 + LPF 에 넣어 재현했다 (`checks/slam_vel_lag.py`, 독립 경로):

| 경로 | 결정적 오차 (재현) | ⊕ 잡음 | ⊕ kf 수준 IMU 몫 4.5 cm/s | 측정 |
|---|---|---|---|---|
| circles8 (\|ω\| RMS 1.27 rad/s, v RMS 0.60 m/s) | 7.64 cm/s (위상자 해석식 7.33) | 8.05 | 9.2 | 9.3 |
| 정사각형 | 9.81 cm/s | 10.13 | 11.2 | 12.0 |

### 2.4 circles8 에서 slam 이 4.5 cm 앞서 달리는 기구

곡선 구간 평균, 기준 진행 방향 t·곡률 중심 쪽 n 성분 (`checks/circle_lead.py`):

| 성분 | kf r1 / r3 | slam r1 / r3 |
|---|---|---|
| 추정 속도 − 참 속도, n 성분 cm/s | −0.59 / −0.02 | **−7.62 / −7.56** |
| 추정 속도 − 기준 속도, n 성분 cm/s | −0.50 / −0.37 | −0.68 / −0.65 |
| 참 속도 − 기준 속도, n 성분 cm/s | +0.09 / −0.35 | **+6.95 / +6.91** |
| 참 위치 − 기준 위치, t 성분 cm | −0.35 / −0.63 | **+4.51 / +4.54** |
| 참 위치 − 기준 위치, n 성분 cm | +2.81 / +2.64 | +2.73 / +2.68 |

1. 월드 속도 벡터가 ω 로 돈다. slam 추정 속도는 τ 만큼 늦은 방향을 가리키므로 참 속도보다 ωτ 만큼 바깥으로 돌아가 있다 (n 성분 −7.6 cm/s, 예측 v·ωτ ≈ 0.60·1.27·0.0898 = 6.8 cm/s).
2. MPC 비용은 추정 속도 − 기준 속도를 줄인다. 그 성분은 두 모드 모두 −0.4~−0.7 cm/s 로 작다.
3. 그 결과 참 속도가 기준보다 n 쪽으로 +6.9 cm/s, 즉 앞선 방향으로 돌고, 원 위에서 그만큼 앞선 위상을 유지한다. 앞섬 상한은 v·τ = 0.60·0.0898 = 5.4 cm 이고 측정값은 4.5 cm (84 %).
4. 안쪽 +2.7 cm 오프셋은 kf·slam 공통이다. 추정기와 무관한 제어기 쪽 성분이다 (속도 −3.5~−4.0 cm/s 는 반경이 2.7 cm 작아진 몫: 0.6·0.027/0.47 = 3.4 cm/s).

contour error 는 두 모드가 같고 (3.2 cm) 시간 기준 오차만 커진다. 경로 모양은 같고 기준보다 앞서 지나간다.

### 2.5 정사각형 가감속 구간 (`checks/square_phase.py`, r1·r2)

| 구간 | 추정 − 참, 진행 방향 v cm/s (kf / slam) | 한 바퀴라도 상한 닿음 % (kf / slam) |
|---|---|---|
| 가속 (기준 가속도 > 0.5) | +0.0~+0.3 / **−7.5~−7.8** | 63~70 / **76~79** |
| 감속 (< −0.5) | −0.5~+0.9 / **+5.7~+6.7** | 53~56 / **65~66** |

가속 중에는 추정 속도가 낮게, 감속 중에는 높게 나온다 (지연과 같은 부호). MPC 는 이 차이만큼 토크를 더 쓰고 상한에 더 자주 닿는다.
시간 기준 추종 오차는 판 사이 범위(8.4~10.3 cm)가 겹쳐서 차이를 말할 수 없다. contour error 는 slam 이 1.36 배다.
감속 구간 진행 방향 위치 오차의 크기 차이(kf −10 cm, slam −3~−4 cm)는 이번에 분해하지 않았다.

## 3. 결론

| 질문 | 답 |
|---|---|
| 추정 정확도 | kf 가 위치 2.3~2.7 배, 속도 2.0~2.5 배 정확하다. 헤딩·각속도는 같다 (둘 다 자이로 적분 + SLAM yaw) |
| 제어 결과 | circles8 시간 기준 추종 오차 slam 1.74 배 (3.5 → 6.2 cm). 정사각형은 contour error 1.36 배, 상한 닿음 11.4 → 14.9 % |
| 슬립 | 두 모드 모두 큰 슬립(> 0.5) 0 %. circles8 에서 slam 의 미끄럼(> 0.1)이 0.6 → 1.4 %, λ RMS 0.022 → 0.028 로 조금 많다. 정사각형은 차이 없다 (λ 최대 0.36~0.38) |
| slam 이 나쁜 원인 | 속도를 두 포즈 차분 + 2 Hz LPF 로 덮어쓰는 구조의 실효 지연 89.8 ms. 시뮬 SLAM 은 튐이 없는 깨끗한 10 Hz 라서, 이 차이는 SLAM 품질이 아니라 속도 산출 방식에서 나온다 |
| 이번에 안 본 것 | 포즈 튐 (`sim_slam_jump`) — kf 는 거부, slam 은 받아들인다. 실차 IMU bias drift. A (PP + 바퀴 PI) |

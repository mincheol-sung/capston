## 3. lag 가 어디서 쌓이나 (`lag_arclen.py`, 2026-11-21)
lag = s_robot − s_ref (− = 뒤처짐). s_ref = 기준점이 그 시각까지 경로를 따라 간 arc length, s_robot = 로봇 위치를 기준 경로 polyline 에 투영한 arc length.
MPCC (Lam·Manzie·Good 2010, CDC) 의 contouring / lag 분해에서 lag 쪽. 로봇 위치는 추정기 (MPC 가 보는 값 = 기준 − Xe) 와 SLAM 중심 두 가지.

| 판 | lag 평균 추정기 / SLAM [mm] | 구간별 lag 변화 합 (추정기) 가속 / 감속 / 꼭짓점 / 그 밖 [mm] |
|---|---|---|
| 171531 예전 μ̂ | −126 / −128 | −448 / −225 / **+802** / −288 |
| 171735 예전 μ̂ | −130 / −132 | −407 / −165 / **+707** / −302 |
| 190506 새 μ̂ | −100 / −101 | −382 / −136 / **+551** / −189 |
| 190642 새 μ̂ | −73 / −73 | +27 / −195 / **+619** / −514 |

읽은 것
1. **lag 는 직선 (가속·감속·그 밖) 에서 쌓이고 꼭짓점에서 풀린다.** 꼭짓점 회전 구간에 들어갈 때 −84~−270 mm, 나올 때 0 근처 또는 +.
   기준이 꼭짓점에서 0.1 m/s 로 줄어드는 동안 로봇이 그 차이를 메운다. 추정기와 SLAM 이 1~2 mm 안에서 같다 → MPC 도 뒤처진 걸 안다.
2. **앞에 꼭짓점이 없는 변 0 에서도 같은 크기로 쌓인다** (새 μ̂ −127·−138, 예전 −226·−270). 실차 (버그 판) 에서는 직선만으로 lag 가 충분히 생긴다.
3. 크기 검산: 변 0 의 −127 mm 를 가속 1.0 s 동안의 일정한 가속 결손으로 보면 ½·Δa·1.0² = 0.127 → Δa 0.25 → 유효 가속 ≈ 1.25 m/s².
   변 최고 속도 1.15~1.23 m/s (`../2026-11-20_square/` 표) 와 같은 크기. 예전 μ̂ 는 LP 최대 가속 1.18 (< 1.5) 로 묶여 ½·0.32·0.933² = 138 mm.
4. 직선 원인 후보 (분리 안 됨). 새 μ̂ τ̄ = [0.1093, 0.1113, 0.1154, 0.1055], 직선 a 1.5 의 U_s = m_eff·a·r/4 = 6.785·1.5·0.04/4 = 0.1018 N·m → RR 여유 0.0037 N·m (4 %).
   - (a) 이 판들의 feedforward 부족 0.25·U_s = 0.0254 N·m > 여유 0.0037 → 모자란 몫을 feedback 이 못 채움 (가속 구간 포화 62 %).
   - (b) 고친 뒤에도 ρ 0.92 → 0.08·U_s = 0.0081 N·m > 0.0037.
   - (c) 모델 밖 손실: 구동계 마찰 보상 잔차, 명령 → 측정 토크 기울기 0.96~0.995 (`../2026-11-19_cmd_chain/`), 질량 오차.
5. 시뮬과 비교 (`../../torque_mpc_sim/2026-11-21_square_stop/`, 고친 뒤, 바닥 μ 0.45): C pass lag −60~−73 mm, C stop −11~−15 mm.
   시뮬에서는 직선만 남긴 stop 의 lag 가 작다 → 시뮬에서는 꼭짓점 쪽이 큰 몫. 실차 (버그 판) 의 직선 lag 와 어긋나는 이유는 위 (a)·(c) 중 무엇인지 모른다.
   **고친 뒤 실차 판 (pass 와 stop) 이 있어야 가른다.**
   → 2026-11-21 18:38 pass 판 (183827, c_s 0.9 상당, 고친 뒤): ρ 0.99 인데 lag 평균 −89 mm 로 그대로 — (a)·(b) 는 주원인 아님. `../2026-11-21_square/RESULTS_KO.md` 3절 4.
6. `../2026-11-20_square/` 표의 e_t (시각 t 기준 접선 투영) 는 꼭짓점에서 접선이 90° 돌 때 앞 변에서 진 거리가 cross-track 으로 넘어가 작게 나온다
   (190506 e_t 평균 −76 vs arc length −101 mm). 꼭짓점을 낀 lag 는 `lag_arclen.py` 로 잰다. `lag_by_phase_tangent.py` 는 같은 판을 e_t 로 나눈 것 (비교용).

## 정정 (2026-11-21)
2026-11-20 (12) 와 2026-11-21 (1) 에 적은 "C 가 못 따라가는 (뒤처지는) 주원인 = 꼭짓점에서 기준이 마찰 상한을 넘는 것" 은 실차 bag 의 lag 로는 맞지 않다.
lag 는 직선에서 쌓이고 꼭짓점에서 풀리며, 꼭짓점이 없는 변 0 에서도 같은 크기다. 꼭짓점에서 U_s 가 상한 밖인 시간 54 % 자체는 사실이고 heading·contour 쪽 문제다.
시뮬 (고친 뒤) 에서는 꼭짓점 정지가 lag 를 크게 줄였으므로 꼭짓점의 몫이 없다는 뜻은 아니다 — 실차에서 두 몫을 아직 못 갈랐다.

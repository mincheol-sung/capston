# MC와 원래 기준 적분의 계산시간 직접 비교 — 2026-10-27

원 실험 코드의 충돌확률 계산 부분만 재측정했다. 경로 생성, 정적 검사, 컨트롤러 비용은 제외했다. 운용 YAML은 변경하지 않았다.

## 조건

- CPU: Intel Core 5 210H. NumPy 1.26.4, SciPy 1.11.4, BLAS/OMP 1 thread.
- 원 `candidate_suite`의 yaw=0, multimodal20 장면: K500, horizon10, dt0.2, 장애물20, 모드2, 충돌 반경0.45m. 후보와 최종 대표6개를 한 번 생성해 모든 방법에 공유.
- 등방 공분산은 원 정확도 실험과 동일. 이방 공분산은 원 시간 실험의 [[0.05,0.025],[0.025,0.025]]를 동일 장면에 적용했다. 모든 원 실험 장면을 재측정한 결과는 아니다.
- MC는 원래 1배 예산(density124, guide min128/max1024, final min256/max4096)부터 32배까지. 5개 guide 그룹을 순차 평가하며 표본 캐시를 재사용하지 않았다. 원 controller의 worker2 전체 실행시간과 직접 대조하지 않는다.
- MC/CDF: warmup2 + 측정10회 평균. 추정기 생성은 제외하되 표본 생성, covariance 전처리, PDF, 거리 비교, 확률 합산은 포함.
- 이방 기준: 원 `disk_reference(order=160)` 그대로, 반경160 × 각도640개 점. 후보 전체를 실제 실행했으며 시간 환산은 하지 않았다. 사전 1개 원 적분으로 warmup 후 전체 크기는 1회만 측정했다. 80차 수렴 검증 시간은 제외.
- CDF는 원 코드 그대로 장애물/모드 루프 내부에서 후보·step 배열을 일괄 평가한다.

## 8배 MC 대비

- 후보500개: 등방 CDF는 8배 MC보다 평균 기준 1.77배 빠름. 이방 MC는 원 극좌표 기준보다 5058.3배 빠름.
- 최종6개: 등방 CDF는 8배 MC보다 평균 기준 4.75배 빠름. 이방 MC는 원 극좌표 기준보다 308.8배 빠름.

이방 수치적분이 비싼 이유는 후보마다 별도 원 내부에서 PDF를 평가하기 때문이다. MC는 그룹 안에서 PDF 평가를 공유하고 후보별 거리 비교를 추가한다. PDF 카운터와 거리 비교/CDF 카운터는 같은 비용의 연산이 아니므로 단순 합산하지 않는다.
이 결과는 원 실험의 고해상도 2차원 기준 적분 구현과의 비교다. 모든 수치적분 알고리즘이 이만큼 느리다는 뜻은 아니다. 저장소에 별도로 존재하는 조건부 Gaussian 1차원 적분(`gaussian_disk.py`)의 시간은 이번 표에 포함하지 않았다.
극좌표 노드 수는 오차 허용치에 맞춰 최적화한 값이 아니라 원 기준값 검증의 160차를 그대로 사용했다. MC와 기준법은 동일한 오차 허용치로 맞춘 비교가 아니며, 원 실험의 계산법 자체를 비교한 결과다.

검증: reference 배열 유한값 확인. 등방/이방 각각 3개 후보-step에 대한 80차 적분과 저장 기준값의 최대 차이 3.11e-15. 자세한 값은 validation.json 참조. 전체 분포의 인증 오차 한계는 아니다.

실제 전·후방 LiDAR 거리 급변 기반 구역 분할 — 구현 초안
2026-11-04

후속 합의: 분할 이후 초기 seed는 gap당 중앙 방향 1개만 사용한다.
아래 5절의 다중 방향 seed 제안 대신 ../midpoint_value_v1/DECISION.txt를 따른다.
이 파일의 거리 급변 분할 규칙과 10장면 결과는 그대로 유지한다.

이번에 구현한 범위
-----------------
tools/experiment_disparity_partition.py에 자동 분할 코드를 구현하고, 실제 기록 10개
snapshot에 동일 설정을 적용했다. 운영 노드나 기존 gap v1 명세를 교체하지 않았다.
색칠된 구역은 seed 생성 전의 공간 구역이다. 안전한 MPPI 궤적이나 최종 guide를
뜻하지 않으며, 구역 개수를 3개로 강제하지 않는다.

장면 선택
---------
기존 실험에서 입력 유효성이 확인된 장면을 bag별 시간 순으로 정렬했다.
mpc_chain_20260923_135325: 20%, 50%, 80% 위치
mpc_chain_20260923_113151: 20%, 50%, 80% 위치
mpc_chain_20260923_135606: 10%, 35%, 65%, 90% 위치
앞서 수동으로 나눈 b1_088은 선택 전에 제외했다. 선택은 분할 결과를 보기 전에
고정했으며, 결과가 1개인 장면도 교체하지 않았다. 독립된 10개 환경이나 독립 평가
데이터라는 의미는 아니다. 같은 bag/주행 구간이 여러 장면에 포함된다.

최종 규칙은 이 10장면의 최초 결과를 보고 개선한 개발 설정이다. 보지 않은 데이터에서
좋다는 검증은 아니다. parameters는 configuration.json에 저장했다.

1. 입력과 통과 가능 깊이
-----------------------
앞·뒤 LaserScan의 원래 beam 인덱스/range/유효성/시각을 보존한다. 기록 odometry와
TF로 각 beam을 현재 로봇 좌표에 deskew한다. 센서 각각의 원시 거리에서 급변을 찾고,
검출된 경계의 위치만 현재 로봇 좌표로 바꾼다. 센서 range 배열끼리 이어 붙이지 않는다.

기존 재현 코드로 관측 free/occupied를 만들고, 기록된 유효 지도만 미관측을 보완한다.
관측 hit와 지도 occupied가 free보다 우선한다. 남은 unknown은 차단한다.
이번 10개 snapshot의 grid/d_free/path는 기존 저장 실험과 대조해 일치를 확인했다.

360개 방향(1도 간격)에서 거리 0~2 m를 0.02 m 간격으로 검사한다.
EDT clearance에서 sqrt(2)*0.04 m + 0.01 m를 뺀 값이
몸체 반경 0.20 m + 추가 여유 0.05 m보다 큰 연속 prefix의 끝을 d_free로 삼는다.
중간 장애물 뒤에서 다시 열린 공간은 현재 방향의 직진 가능 깊이에 포함하지 않는다.

d_free >= 0.50 m인 원형 연속 각도 bin을 모은다. 6개 미만인 연결 구간은 제외한다.
±180도 경계에서 이어지는 구간은 하나다. 전체 360도가 열려 있으면 시작점을
물리적 경계로 취급하지 않는다. 유효 연결 구간이 전혀 없을 때만 추가 여유 0.05 m를
제외하고 한 번 재시도한다. 몸체 반경/격자 보수성/unknown 처리는 그대로다.
이번 10장면에서는 이 재시도가 필요하지 않았다.

2. 원시 거리 급변 검출 — detect_edges()
-------------------------------------
각 센서의 인접 beam i, i+1을 검사한다. 2 m나 6 m로 자르기 전의 원래 range다.
왼쪽 세 beam [i-2,i-1,i], 오른쪽 세 beam [i+1,i+2,i+3]이 모두 유효해야 한다.
무효값, inf, 센서 연결부를 건너뛰어 차이를 계산하지 않는다.

  mL = median(왼쪽 3개 range)
  mR = median(오른쪽 3개 range)
  T  = max(0.40 m, 0.12 * min(mL,mR))
  Δadj = r[i+1] - r[i]
  Δmed = mR - mL

다음 조건을 모두 만족할 때 원시 급변 후보다.
  abs(Δadj) >= T
  abs(Δmed) >= T
  Δadj와 Δmed의 부호가 같음
  max(왼쪽 max-min, 오른쪽 max-min) <= 0.35 * abs(Δmed)

따라서 한 beam의 튐이나 여러 beam이 번갈아 바뀌는 지점을 무조건 경계로 만들지 않는다.
최적화: 먼저 유효 인접 차이가 0.40 m 이상인 인덱스만 벡터 연산으로 추린다.
그 소수 후보에만 3-beam median/일관성 검사를 수행한다.

가까운 쪽 beam의 실제 hit 좌표를 p_near라 하면
  θraw = atan2(p_near.y, p_near.x)
이다. 센서의 angle_min 자체를 로봇 중심의 경계 방향으로 사용하지 않는다.
경계 강도 score = abs(Δmed)/T를 저장한다.

3. 로봇 주변 공간에 의미가 있는 급변인지 확인 — project_edges()
----------------------------------------------------------------
원시 거리 급변만 사용한 최초 결과는 먼 배경 때문에 최대 16개 구역까지 잘게 갈라졌다.
이 결과는 results_raw_edges_only.json에 보존했다. 그래서 원시 급변에 더해
로봇이 탐색하는 2 m 주변의 몸체 진입 깊이 변화가 연결되는지 요구한다.

θraw에 가장 가까운 1도 bin을 j0라 하고, j0±8 bins 안의 경계 j를 검사한다.
경계 j의 왼쪽 깊이 5개 [j-5...j-1], 오른쪽 깊이 5개 [j...j+4]를 비교한다.
원형 인덱싱하며 양쪽 10개 모두 d_free >= 0.50 m여야 한다.

  Δdepth(j) = median(오른쪽 깊이 5개) - median(왼쪽 깊이 5개)

원시 거리 변화와 Δdepth의 부호가 같고 abs(Δdepth) >= 0.25 m인 경계가 있어야 한다.
여러 개면 깊이 차이가 가장 큰 지점을 선택하고, 동률이면 원래 방향과 가까운 지점을
선택한다. 이는 hit의 경계와 몸체 여유를 반영한 공간 경계의 차이를 최대 8도로
보정하는 규칙이며, 물리적으로 정확한 경계를 보장하는 식은 아니다.

원시 급변의 근거 없이 d_free 변화만 보고 새로운 경계를 만들지 않는다.
양쪽 모두 2 m로 잘려서 같은 깊이면 해당 급변은 분할에 사용하지 않는다.
단, 2 m 제한과 격자/지도 처리가 최종 경계 위치에 영향을 줄 수는 있다.
따라서 이 방식은 '순수 원시 거리 급변 분할'이 아니라
'원시 거리 급변 + 주변 몸체 진입 깊이의 근거를 요구하는 분할'이다.

PNG의 ★는 원시 급변 방향, 점선은 보정된 분할 경계다. 둘은 최대 8도 다를 수 있다.

4. 가까운 경계 정리 및 원형 구간 분할 — partition()
---------------------------------------------------
각 열린 연결 구간 안의 경계를 score 높은 순으로 검사한다.
이미 남긴 내부 경계와 각도 차이가 20도 미만이면 약한 경계를 제거한다.
열린 구간 끝에서 6 bins 미만 위치의 경계도 제거한다. 최종 조각은 최소 6 bins다.
20도는 내부 급변 경계끼리의 간격이고, 연결 구간 끝까지 20도를 강제하는 조건은 아니다.
따라서 자연적으로 좁게 열린 9 bins 구간도 결과에 남을 수 있다.

열린 구간이 360도 전체이면 원형 간격으로 중복을 검사한다.
남은 내부 경계가 0~1개이면 공간 구역은 하나다. 최소 2개 경계가 있어야 원을 분할한다.
매 결과에 대해 출력 bin의 합집합이 유효 열린 구간과 정확히 같고, 중복되지 않는지
검사한다. 최소 폭 미달인 별도의 연결 구간을 제외하고 열린 공간을 임의로 버리지 않는다.

최종 반환 예:
  region: id, component, bins, first_angle_deg, last_angle_deg,
          bin_count, min_depth_m, max_depth_m
  edge: sensor, beam_before, range_before/after, median_before/after,
        angle_deg, raw_cut_bin, cut_bin, projection_bins, score, status

배열의 각도는 반시계 방향으로 증가한다. first > last이면 ±180도를 건너는 구간이다.
id는 각 snapshot 안에서만 유효하며, 다음 프레임의 동일 번호가 같은 공간이라는 뜻이 아니다.

5. MPPI에 붙일 때의 구체적인 변경점 — 아직 운영 코드에 적용하지 않음
------------------------------------------------------------------
dra_mppi_node.py:
  현재 노드는 traversability와 prediction을 받지만 이 프로토타입의 원시 scan 급변
  입력은 별도로 필요하다. 전·후방 scan 버퍼/TF/odom 동기화와 유효성 검사를 추가하거나,
  같은 시각의 scan-derived 경계와 free-space 메타데이터를 upstream에서 전달받는다.
  기존 지도의 좌표/시각 및 로봇 반경 처리를 맞춰 중복 inflation을 피한다.
  유효하지 않은 센서 입력과 '유효 입력이지만 구역 없음'을 구분한다.

새 gap_proposals 모듈:
  위 detect_edges/project_edges/partition의 순수 배열 연산을 옮긴다.
  각 구역에서 중앙 방향, 가장 깊은 방향, 경로 방향에 가까운 내부 bin을 후보로 만든다.
  같은 bin은 한 번만 사용한다. 각 방향의 목표 거리를 기존 2초 제약 rollout 도달성으로
  줄이고 몸체 충돌, 목표 오차 <=0.35 m, nominal 중복을 검사한다.
  기존 공통 비용+정적 soft 비용 순으로, 선택된 seed와 RMS<0.25 m인 후보를 제거한다.
  최대 3개 guide를 선택한다. 구역마다 반드시 하나를 배정하지 않는다.
  구역이 하나여도 여러 seed/guide가 나올 수 있고, 구역이 6개여도 guide는 최대 3개다.

guide_conditioned.py:
  __init__에서 고정 guide_angles_deg 개수로 sampler/state를 만드는 구조이고,
  anchors()가 고정 방향을 제어입력열로 만든다. 동적인 구역 수를 angles 설정에 덮어쓰는
  것만으로는 충분하지 않다. compute()에 제약 완료 seed_controls와 active mask,
  allocation을 전달하는 경로를 추가하고 nominal+최대3 guide 슬롯을 준비한다.
  작업자/MC 평가기를 매 주기 새로 만들지 않고 기존 2 worker를 재사용한다.
  guide 1개당 100 rollout, nominal은 500-100*g; 총 500을 유지한다.
  기존 MC 평가와 최종 공통 재평가/Stop/hold 판정은 유지한다.

상태와 연속 프레임:
  이전 실행용 최적 제어열은 현재 시점에 맞춰 nominal로 이동한다.
  구역 번호로 이전 guide warm start를 재사용하면 엉뚱한 공간으로 연결될 수 있다.
  이전 궤적을 현재 좌표로 바꿔 기하적으로 대응시키고, 대응이 불확실하면 새 seed로
  초기화한다. 경계가 생겼다 사라지는 현상에 대한 hysteresis/관측 신뢰도 관리는
  연속 프레임 재생으로 검증할 다음 단계다. 이번 snapshot 구현에는 포함하지 않았다.

충족되지 않으면 분할하지 않는 한계다. 기존 골짜기 분할을 몰래 추가하지 않았다.

fallback은 별도 단위 검증에 포함했다. 이 10개로 gap 없음 빈도나 주행 성공률을
추정할 수 없다. 새 방식의 MPPI 최종 비용/안전성/주행 성능은 아직 비교하지 않았다.

이전 수동 예시 b1_088에 대한 별도 진단에서도 자동 경계가 수동 좌표와 정확히
일치하지 않는다. 이 개발 규칙으로는 4개(95..165,166..-99,-98..-17,-16..-11)가
나온다. 이 예시는 10개 PNG에 포함하지 않았으며, 세 구간으로 강제 맞추지 않았다.

7. 검증과 실행
-------------
6개 단위 검사: ±180도 연결, uncapped 거리 급변과 먼 배경 제거, 단일 spike 제거,
무효 beam 연결 방지, 전체 원 두 경계의 정확한 분할, zero-gap/fallback.
입력 grid/depth/path를 기존 저장 실험과 대조했고, 각 출력 구간의 중복/누락도 검사했다.

partition_timing.json: 10개 입력 x 20회, 메모리 내 급변검출+기하 보정+분할 시간이다.
scan 수신/deskew/grid/EDT/seed/MPPI/ROS/그림 생성은 포함하지 않는다.
이 측정으로 전체 5 Hz를 보장하지 않는다.

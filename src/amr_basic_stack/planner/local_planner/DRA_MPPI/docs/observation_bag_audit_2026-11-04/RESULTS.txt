결론
- 실제 bag 3개 전체의 관련 메시지를 읽어 확인했다. 대상 선정용 입력과 기록상

- 기록된 카메라 관측은 고정되어 있다. 새 heading에서 무엇이 보였을지 또는
  관측 heading의 이득은 이 bag만으로 검증할 수 없다.

규칙별 가능한 확인 범위
- 최근 유효 LiDAR 추적 / 카메라 정보 없음·오래됨: 기록된 ages/source/lifecycle로 가능.
- 접근 방향·시점·최근접 거리: 위치/속도/공분산, odometry, 경로, TF로 계산 가능.
  이번 감사에서는 계산하지 않았다. 실제 충돌·행동 정답은 별도로 필요하다.
- 여러 후보의 선정·유지·전환: 규칙 구현 후 입력을 순서대로 읽는 shadow replay로 검토 가능.
  실제 heading을 바꾸지 않은 데이터라는 한계가 있다.
- 같은 ID의 종류 정보 갱신: 사례 확인 가능. ID 연결이 올바른지는 보장하지 않는다.
- 서로 다른 카메라 프레임에서 3회 확인: 직접 증명할 연결 정보 부족.
  원본 /detections의 시간은 존재하지만 구형 트랙에는 대응되는 원본 카메라
  observation_id/capture stamp가 없다. 별도 재연결·재추적 결과는 추정으로 구분해야 한다.
- 시간초과·대상 손실·재시도 억제: 규칙 구현 후 상태 전이 논리 검증 가능.
- 시야 가림 / 검출 정답 / 새로운 방향의 관측 이득: 현재 자료만으로 확정 불가.

카메라 및 기록 한계
- 세 bag 모두 CameraInfo/검출 결과는 있지만 sensor_msgs/Image 또는
  CompressedImage 토픽은 없다. CameraInfo/metadata는 영상이 아니다.
- 세 bag 모두 관측 대상 topic이 없고 신규 ObservationProvenance가 없다.
- 내장 CameraInfo의 핀홀 수평 FOV 추정은 약 79.2도(반각 약 39.6도).
  검출이 유효한 FOV나 가림 여부를 뜻하지 않는다.
- 기록된 정적 TF: base_link→camera_link XYZ=(0.11398,0.0475,0.092772),
  camera_link→camera_color_frame XYZ=(0,-0.059,0), 두 회전 모두 항등.
  기록 당시 color camera 평면 offset은 합산하면 (0.11398,-0.0115)m다.
  현재 장착 상태와 같다는 보장은 없다. 운영 YAML은 변경하지 않았다.
- 미분류 트랙이 많으므로 '미분류=관측 대상'만 사용하면 벽/가구 클러스터도 선정된다.
  경로 관련성, 추적 유지시간, 관측 여유시간 조건까지 적용한 후 후보 수를 봐야 한다.

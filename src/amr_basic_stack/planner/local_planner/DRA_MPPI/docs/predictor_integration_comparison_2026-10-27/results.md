# IMM 예측 입력에서 MC와 효율적인 직접 적분 비교 — 2026-10-27

현재 ImmMotionPredictor와 predictor.yaml로 이방·3모드 미래 위치를 생성해, 공유 MC와 GaussianDiskCollisionProbability를 같은 입력에서 비교했다. 실제 사람 bag/실측 posterior가 아닌 합성 IMM posterior를 사용했다. 운용 설정은 변경하지 않았다.

## 조건

- Intel Core 5 210H, NumPy 1.26.4/SciPy 1.11.4, BLAS/OMP 1 thread. guide 5그룹 순차 실행, MC 캐시 재사용 없음.
- 장애물 5/20개 × 횡단/정면 접근/회전 3장면, 총6장면. yaw0, 후보500개와 대표5개+Stop은 한 번 생성해 고정했다.
- CV/CT/STATIC 3개 모드를 모두 포함. 각 모드 평균·공분산을 실제 예측 코드로 0.2초씩 10 step 전파했다. 원 예측 YAML의 fixed posterior weights 사용. 온라인 노드의 객체/모드 필터링과 지연 보정은 재현하지 않았다.
- 합성 posterior: 회전시킨 위치 표준편차 0.12/0.05m, 속도 0.20/0.08m/s, 각속도 0.25rad/s, 교차 블록0. 모드별 속도/회전율과 가중치는 benchmark 코드에 명시했다. 관측을 통해 추정한 posterior는 아니다.
- 충돌 반경0.45m, 공분산 최소 표준편차0.08m를 MC와 적분에 동일 적용. 서로 다른 장애물은 독립으로 합산.
- 확률 계산 부분만 측정, 준비1회 후 5회 평균. 예측·경로 생성·추정기 생성·컨트롤러 나머지 처리는 제외했다. 전체 controller 지연/5Hz 준수 시험이 아니다.
- MC 1/2/4/8/16/32배: guide density124/min128/max1024, final density124/min256/max4096을 기준으로 비례 증가.
- 직접 적분: 저장소 gaussian_disk.py의 조건부 Gaussian 1차원 적분. 한 축은 정규 CDF로 처리하고 나머지 축만 16→32→64→…512차로 적응 적분한다. 등방 성분에는 CDF, 매우 먼 성분에는 Gaussian 반공간 확률 상한을 적용한다. 근접 위험 성분에 적분점을 집중한다.
- 적분 수렴차 기준1e-8, 미수렴 성분은 충돌확률1로 처리하는 기존 구현. 이는 인증된 오차 한계가 아니다.

## 독립 기준값 확인

- 각 scene/profile에서 5% 부근, 확률 범위 전반, 고정 난수로 후보-step을 선택해 총 139지점을 검증했다. MC 오차를 보고 검증 지점을 고르지 않았다.
- 원래 2차원 polar 적분80/160차의 최대 차이: 3.331e-15.
- 직접 적분과 polar160의 최대 절대 차이: 8.236e-07 (= 0.000082%p). 모든 timing 호출에서 미수렴 적분0건.
- 이 검증은 선택된 지점에 대한 것이며 모든 후보-step의 독립 기준 오차 상한을 증명하지 않는다.

## 해석

- 많은 경로 후보를 평가할 때 MC의 PDF 공유 이점이 확인됐다. 장애물20개에서 MC8은 직접 적분보다2.4~2.8배 빨랐다. 5천 배 차이는 고비용 기준 검증 코드와 비교했기 때문이며 효율적인 적분과의 차이가 아니다.
- 최종6개에서는 공유할 후보가 적으므로 직접 적분이 유리했다. MC8 대비5.5~6.4배 빨랐고 표본 오차도 제거했다.
- 따라서 이 입력에서는 guide에 MC, 최종 후보 검증에 직접 적분을 사용하는 구성이 유망하다. 이는 두 계산법의 분리 측정에 근거한 제안이며 실제 hybrid controller 선택 결과/실행시간 검증은 수행하지 않았다.
- MC32에서는 후보500개 계산이614~645ms로 직접 적분300~340ms보다 느렸다. 높은 정확도가 필요할수록 MC의 속도 이점은 줄어든다.
- 합성 predictor 입력만으로 실제 사람 예측의 확률 보정, 예측 정확도, 실주행 충돌 회피 성공을 주장하지 않는다.

## 실차 런치의 CAN 자동 준비

`torque_experiment.launch.py plant:=real`은 기본 `auto_setup_can:=true`로,
모터 노드를 시작하기 전에 설치된 `tools/setup_can.sh`를 실행한다.
기존에는 can0가 없거나 DOWN이면 모터 노드 연결/송신이 실패했으므로 시작 순서를 보완했다.

- 인터페이스가 이미 UP이면 USB 탐색이나 관리자 명령 없이 기존 설정을 사용한다.
- DOWN이면 `ip link set ... up`을 실행한다.
- 없으면 CANable by-id 자동 선택 → 모듈 준비 → `slcand -s8` → 지정 인터페이스 활성화.
- 명령 실패 또는 10초 제한 초과 시 모터/제어 노드를 시작하지 않고 오류를 표시한다.
- 시뮬레이션에서는 실행하지 않는다. 수동 준비를 쓰려면 `auto_setup_can:=false`.
- 별도 장치가 필요하면 `can_device:=/dev/serial/by-id/...`, 인터페이스는 `can_interface:=can0`로 지정한다.

관리자 작업은 `sudo -n`으로 실행한다. 런치 내부에서 비밀번호를 물으며 멈추지 않는다.
CAN 준비에 권한이 필요하면 같은 터미널에서 `sudo -v`로 인증한 다음 런치한다.
인증 정책에 따라 자식 프로세스에서 캐시를 사용할 수 없다면 기존 수동 스크립트를 먼저 실행한다.
이미 UP인 인터페이스라면 인증이 필요 없다. sudoers 변경이나 비밀번호 저장은 하지 않는다.
기존 인터페이스의 bitrate/물리 장치 대응은 재설정하지 않는다.

```bash
# 처음 빌드 또는 변경 후 재빌드하고 workspace의 install/setup.bash를 source한 상태에서:
sudo -v
ros2 launch amr_mpc torque_experiment.launch.py plant:=real
```

이는 CAN 준비 자동화다. 기존 게이트는 기본 비무장이며, 실제 모터 노드 시작 시 ENTER/DAMPING은 송신된다.
코드 검증은 모의 ip/sudo/slcand로 수행했고 실제 CAN 활성화나 모터 구동은 수행하지 않았다.

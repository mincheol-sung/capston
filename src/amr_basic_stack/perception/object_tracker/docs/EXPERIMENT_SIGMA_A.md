## 0. 무엇을 재는가

두 가지다. 같은 bag 으로 둘 다 나온다.

| # | 양 | 왜 필요한가 | 현재 값 |
|---|---|---|---|
| 1 | `sigma_a` — CWNA process noise intensity [m/s^1.5] | 판정 하한 · association 게이트 폭 · 예측 신뢰구간을 **동시에** 지배 | 1.0 (임시, 근거 없음) |
| 2 | 보행자 effective R(d) | 위 셋의 계산이 전부 이 R 위에 서 있다 | C2 의 **강체** R 을 그대로 씀 |

## 1. 왜 C2 로 부족한가

C2 문서가 명시적으로 배제했다:

> **타깃**: backpack (정지 강체). person 을 쓰지 않는 이유 — 호흡·미세한 자세
> 변화가 σ 에 섞이는데 그건 measurement uncertainty 가 아니다.

**그 판단은 C2 의 목적에서는 옳다.** 센서·파이프라인의 고유 불확실성을 재는 것이
목적이었으므로 타깃이 움직이면 안 된다.

**그런데 트래커가 필요로 하는 양은 다르다.** 트래커의 R 은 "이 검출이 실제 물체
위치에서 얼마나 흩어지는가"이고, 대상이 사람이면 몸 흔들림이 그 흩어짐의 일부다.
분리할 수 없고, 분리해서도 안 된다.

### 흔들림이 R 로 갈지 sigma_a 로 갈지는 주파수가 정한다

12 Hz 샘플링 기준:

- **프레임 간 무상관(white)** 성분 → `R` 로 들어간다
- **프레임 간 상관(slow)** 성분 → 가속처럼 보여 `sigma_a` 로 들어간다

진폭 A, 주파수 f 의 정현 진동은 최대 겉보기 속도 `2 pi f A` 를 만든다:

| f [Hz] | A=10mm | A=30mm | A=50mm | A=100mm |
|---|---|---|---|---|
| 0.5 | 31 mm/s | 94 mm/s | 157 mm/s | 314 mm/s |
| 1.0 | 63 | 188 | 314 | 628 |
| **2.0** | 126 | 377 | **628** | **1257** |
| 3.0 | 188 | 565 | 942 | 1885 |

참고: DYNAMIC 판정 하한 471~602 mm/s, 보행 속도 1200 mm/s.
나이퀴스트 6 Hz 이므로 보폭 2~3 Hz 는 aliasing 없이 관측된다 (한 주기 4~6 프레임).

**서 있을 때**(자세 동요 0.5~1 Hz, 10mm 급)는 31~63 mm/s — 하한 한참 아래라 안전.
**걸을 때**(보폭 2 Hz, 대표점 진폭 50~100mm 추정)는 628~1257 mm/s — **보행 속도급**.
이 성분은 `sigma_a` 로 흡수된다. 실측값이 1.0 보다 커져도 그게 틀린 게 아니라
"사람을 놓치지 않으려면 필요한 값"이다.

> 진폭 50~100mm 는 **추정이지 실측이 아니다.** 실제로 얼마인지가 D-2 가 재는 것이다.

## 2. 가장 중요한 원칙

> **`sigma_a` 는 물리 상수가 아니다. bag 에 담긴 운동이 답을 정한다.**

일직선 등속 보행만 녹화하면 작은 `sigma_a` 가 나오고, 실제 주행에서 사람이
방향을 틀 때 트랙이 끊긴다. 반대로 일부러 지그재그를 뛰면 큰 값이 나오고
판정 하한이 보행 속도를 넘어 아무것도 DYNAMIC 으로 못 본다.

**녹화할 운동 = 로봇이 실제로 만날 운동.** 이 실험의 성패가 여기서 갈린다.

## 3. 고정할 설정 — 실험 중 변경 금지

### 3.1 파이프라인 (C2 와 동일해야 R 비교가 성립한다)

| 노드 | 파라미터 | 고정값 |
|---|---|---|
| `rgbd_detection_node` | `camera_position_method` | `roi_median_3d` |
| | `depth_roi_ratio` | `0.5` |
| | `min_valid_depth_pixels` | `20` |
| | `yolo_conf` | `0.15` |
| `lidar_cluster_node` | `cluster_position_method` | `mean_centroid` |
| | `lambda_deg` / `sigma_mult` / `sigma_r` | `20` / `3` / `0.03` |

C2 와 다른 값을 쓰면 D-3 대조군이 의미를 잃는다.

### 3.2 로봇

**정지 상태로 녹화한다.** `nis_fit.py --bag` 은 `base_link` 좌표를 그대로 쓰므로
로봇이 움직이면 자기운동이 표적 운동으로 섞여 `sigma_a` 가 과대추정된다.

`/tf`, `/tf_static` 을 같이 녹화해 두면 나중에 odom 변환을 붙일 수 있지만,
**1차 실험은 정지로 한다.** 변수를 하나씩 푸는 것이 빠르다.

### 3.3 배치

- 타깃 **뒤쪽 1 m 이상을 비운다.** C1 에서 라이다 σ 의 75%를 잃은 원인이 이것이다
  (벽을 잡으면 σ 가 **오히려 작게** 나와 σ 만 보면 못 잡는다).
- 바닥에 2 / 4 / 6 m 를 테이프로 표시. 줄자 실측값을 기록한다 (반올림 금지).

## 4. 측정 프로토콜

### D-1 — 보행자 기동 (`sigma_a` 본 측정)

| 항목 | 값 |
|---|---|
| 타깃 | 사람 1명 |
| 구간 | 2~5 m 대역 (카메라·라이다 둘 다 살아 있는 구간) |
| 길이 | **90 초** 이상 |
| 반복 | 3 run (사람 바꿔서 하면 더 좋다) |

**포함해야 할 운동** — 각각 여러 번:

| 운동 | 왜 |
|---|---|
| 직선 보행 (평상시 속도) | 기저 |
| 좌우 방향 전환 (90도 선회) | 1.70 m/s^2. CV 모델이 못 따라가는 대표 케이스 |
| 정지 → 출발 | STATIC ↔ DYNAMIC 전이 |
| 로봇 쪽으로 접근 / 멀어짐 | 반경 방향. 횡 방향과 R 이 다르다 |
| 로봇 앞을 횡단 | 횡 방향 |

**포함하지 말 것**: 달리기, 일부러 하는 지그재그, 급정지 연기.
로봇이 실제로 만날 운동만.

표본 수 (트랙 1개 12 Hz 기준):

| `sigma_a` 정밀도 | 필요 프레임 | 시간 |
|---|---|---|
| ±6.6% | 49 | 4 s |
| ±4.7% | 98 | 8 s |
| **±2.7%** | **296** | **25 s** |
| ±1.5% | 958 | 80 s |

90초면 검출률 50% 여도 ±2.7% 아래로 들어간다.

### D-2 — 정지 보행자 (effective R)

| 항목 | 값 |
|---|---|
| 타깃 | 사람 1명, **자연스럽게 서 있기** |
| 거리 | 2, 4, 6 m 각각 |
| 길이 | 30 초 (표본 360 → σ 를 ±3.7% 로) |
| 반복 | 조건당 2 run |

**숨을 참거나 부동자세를 취하지 말 것.** 자연스러운 자세 동요가 우리가 재려는
양의 일부다. 팔은 자연스럽게 내리고, 정면을 본다.

정지 타깃의 위치 표본 분산이 곧 effective R 이다. 별도 GT 가 필요 없다.

표본 수:

| 목표 정밀도 | N | 12 Hz 로 |
|---|---|---|
| ±10% | 51 | 4.2 s |
| ±5% | 201 | 16.7 s |
| ±3% | 557 | 46.4 s |

### D-3 — 강체 대조군 (control) **← 빼지 말 것**

| 항목 | 값 |
|---|---|
| 타깃 | **C2 와 같은 backpack** (물리적으로는 백팩) |
| 거리 | 2, 4, 6 m |
| 길이 | 30 초 |

> **YOLO 는 이 백팩을 `suitcase` 로 분류한다.** C2 에서 `--class-name backpack`
> 을 줬다가 카메라 표본이 전 거리에서 0 이 나와 "원거리 검출 실패"로 오독하고
> 몇 시간을 헛돈 전례가 있다. 클래스 필터를 쓰는 스크립트에는 반드시
> `suitcase` 를 줄 것. 확신이 없으면 `check_target.py --label probe` 로
> `top_class` 를 먼저 확인한다.

**이게 없으면 D-2 결과를 해석할 수 없다.** 두 경우를 구분해야 한다:

| D-3 (backpack) 결과 | 해석 |
|---|---|
| C2 예측과 일치 | 파이프라인 정상. D-2 와의 차이는 **순수한 몸 흔들림** |
| C2 예측과 불일치 | **파이프라인이 C2 때와 달라졌다.** 먼저 이걸 고쳐야 한다 |

C2 예측값 (비교 기준):

| d [m] | 융합 σ_r | 융합 σ_t | 카메라 σ_r | 라이다 σ_r |
|---|---|---|---|---|
| 2.0 | 0.42 mm | 1.49 mm | 2.15 mm | 0.42 mm |
| 4.0 | 0.54 mm | 3.52 mm | 14.35 mm | 0.54 mm |
| 6.0 | 1.60 mm | 4.92 mm | 43.59 mm | 1.60 mm |
| 7.0 | 1.60 mm | 6.50 mm | 검출 못함 | 1.60 mm |

(r = 반경 방향, t = 횡 방향. 카메라 검출 한계 6.5 m)

### D-4 — 교차 (association 확인, 있으면 좋음)

사람 2명이 로봇 앞에서 교차. 30 초 × 2 run.
정량 지표가 아니라 **ID 가 바뀌는지 눈으로 보는** 용도다.

## 5. 녹화

```bash
# 터미널 1 — 인지 스택
ros2 launch amr_perception_bringup perception_stack.launch.py \
    yolo_conf:=0.15

# 터미널 2 — 녹화 (조건마다 이름을 바꾼다)
ros2 bag record -o ~/bags/sigma_a_D1_run1 \
    /detections_fused /detections /lidar_clusters /tf /tf_static
```

| 토픽 | 왜 |
|---|---|
| `/detections_fused` | **필수.** `nis_fit.py` 의 입력 |
| `/detections`, `/lidar_clusters` | `camera_lidar_fusion` 파라미터를 바꿔 오프라인 재실행하려면 필요 |
| `/tf`, `/tf_static` | 나중에 odom 변환을 붙이려면 필요 |

전부 텍스트급이라 크기는 무시할 수준이다 (수 MB / 90초).

**조건마다 별도 bag 으로.** 한 bag 에 몰아 넣으면 D-1 과 D-2 를 분리할 수 없다.

## 7. 수용 기준

### D-1 이 성공했는지

수렴 시 **세 지표가 동시에** 맞아야 한다:

| 지표 | 목표 | 벗어나면 |
|---|---|---|
| 평균 NIS | **1.907** (2.0 아님) | 필터가 일관적이지 않다 |
| 기각률 | 1.0% | 위와 같은 얘기. 게이트가 chi^2_2(0.99) 라서 |
| `c` | 1.000 | 위와 같은 얘기 |

추가로 **run 간 재현성**: 3 run 의 `sigma_a` 가 서로 ±20% 안에 들어와야 한다.
벗어나면 각 run 의 운동 내용이 다른 것이고, D-1 의 시나리오 통제가 실패한 것이다.

**거리 무관성 검사**: `sigma_a` 는 표적의 성질이지 센서의 성질이 아니다.
bag 을 근거리/원거리 구간으로 쪼개 따로 fit 했을 때 값이 크게 다르면
**R 모델이 틀린 것**이다 (D-2/D-3 을 먼저 봐야 한다).

### 결과별 다음 행동

| `sigma_a` 실측값 | 판정 하한 | 뜻 | 할 일 |
|---|---|---|---|
| < 0.5 | < 0.30 m/s | 좋다 | 그대로 반영 |
| 0.5 ~ 1.5 | 0.3~0.7 m/s | 예상 범위 | 반영. 4초 예측 폭 재확인 |
| 1.5 ~ 3.0 | 0.7~1.5 m/s | 하한이 보행 속도에 육박 | **association 용/판별용 `sigma_a` 분리** 검토 |
| > 3.0 | > 1.5 m/s | 하한이 보행 속도 초과 | CV 모델의 한계. 대표점 정의부터 재검토 |

### D-2 / D-3 결과별

| 상황 | 뜻 | 할 일 |
|---|---|---|
| backpack ≈ C2, person ≈ backpack | 몸 흔들림이 작다 | 아무것도 안 해도 된다 |
| backpack ≈ C2, person >> backpack | 몸 흔들림이 지배적 | `camera_lidar_fusion` 에 **클래스별 R 보정** 추가 (person 은 x배) |
| backpack ≠ C2 | 파이프라인이 변했다 | **여기부터 고친다.** 다른 결과는 전부 보류 |

## 8. 함정

- **로봇을 움직이지 말 것.** 자기운동이 `sigma_a` 로 흡수된다.
- **파라미터를 실험 중에 바꾸지 말 것.** 특히 `yolo_conf`. C2 가 세션 중간에
  τ 를 0.4 → 0.15 로 바꿔 `P_det(d)` 를 통째로 버린 전례가 있다.
- **`yolo_conf` 는 런타임 변경이 먹지 않는다.** 파라미터 콜백이
  `camera_position_method` / `depth_roi_ratio` / `min_valid_depth_pixels` 셋만
  처리한다. `ros2 param set` 은 성공했다고 보고하고 `ros2 param get` 도 새 값을
  보여주지만 검출기의 `self.conf` 는 안 바뀐다 (생성자에서 1회 읽음).
  **반드시 launch 시점에 넘길 것.**
- **`--class-name` 은 문자열 정확일치.** 위 D-3 의 `suitcase` 주의사항 참고.
- **타깃 뒤 1 m 를 비울 것.** 벽을 잡으면 σ 가 작게 나와서 σ 만 봐서는 못 잡는다.
- **D-3 을 빼지 말 것.** 대조군 없이는 D-2 를 해석할 수 없다.
- **조건마다 bag 을 나눌 것.**
- `sigma_a` 가 1.0 보다 크게 나와도 놀라지 말 것. 대표점이 보폭 주파수로
  진동하면 그게 정상이다. 그 값이 "사람을 놓치지 않는 데 필요한 값"이다.
